# Allure visual direction

The product is a cross-framework design system. Its audience needs to recognize the brand, evaluate a real component, and reach the correct installation command. These are design hypotheses for acceptance, not findings from a user study.

## Reference pull

- Linear: a visible distinction between page ground, working surface and contextual overlay.
- Vercel: strong light-theme contrast and a clear typographic silhouette.
- Raycast: a restrained accent around the action that deserves attention.
- Motion: product behavior demonstrated with usable controls.
- basement.studio: confident scale and room around the main idea.

The references inform individual decisions. The palette, feather, local fonts and composition belong to Allure.

## Composition

Product UI Slate is the structural concept. The first scene contains the existing headline, local 3D feather, introduction and a working component slate. The next scene preserves the reversible framework, installation and FAQ flow. The closing action and project footer stay concise. Mobile uses the same reading order in one column.

Keep the copy anchors “One language.”, “Every interface.” and “See the details in action”, using the existing twelve-language dictionaries. The floating island header retains navigation, language, theme and RTL controls. Do not introduce testimonials, customer logos, invented metrics or an additional signup flow.

## Identity and materials

Preserve the supplied feather artwork and its holes. The subject is the Allure logo itself, rendered locally from the supplied SVG; no external scene, photography or runtime is needed. Its transparent backdrop fits either theme. Use the existing SVG as the fallback, reserve the canvas dimensions, and visually verify the front silhouette and framing after the build.

Days One is display, Manrope is body and the existing system monospace stack is technical text. The semantic palette and numeric material values live in foundation tokens. Graphite and porcelain carry the layout; primary identifies actions. Sage, steel blue, champagne and rose identify status. Do not use a rainbow wash, decorative separator rules, cream-and-brass styling or heavy glass behind reading text.

## Interaction and motion

A short stepped glint is the shared visual detail. Primary actions use a clear fill and a small highlight. Cards and overlays use separate elevations. Filled, hovered, pressed, focused, disabled and invalid states remain distinguishable.

The feather entrance lasts at most 4.4 seconds. It then rests and accepts manual rotation. The framework choices do not orbit. A slider changes the slate light immediately, tabs change its framework record, and the catalogue action follows the selected framework. Other page motion follows interaction. Ordinary feedback uses 120/180 ms and the guided sequence uses 360 ms. Keep transforms and opacity local, and pause hidden effects.

## Acceptance scenarios

A visitor recognizes the same materials and states on the landing, React catalogue and Flutter catalogue. They can switch theme, select a framework, inspect a component and copy its installation command without losing orientation. Verify the same flow with the keyboard, RTL and reduced motion.

Inspect desktop and 320 px screenshots in both themes. The feather must be complete and legible, the UI slate must fit without page-wide scrolling, and text must remain readable. Review data alignment, form labels and feedback with enlarged text. A visual pass does not establish device performance or user-study results.
